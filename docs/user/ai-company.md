# AI 公司模块

入口在 T3 Code 左侧栏底部，用量图标右侧的「AI 公司」。点击后在 T3 主区域打开公司全景，地址为 `/company`。此功能随中文版构建，没有独立插件安装包；普通聊天仍走 T3 原生 Provider，公司任务由后台调度与 herdr-core 执行。

## 公司全景与业务范围

默认进入公司全景：你 → 公司统筹 → 部门 → 负责人／渠道 → 执行岗位。小红书是自媒体获客与运营下面的一个渠道。主营业务尚未确定，当前按已确认的方向先搭可扩展组织框架，后续按需增加业务部门与岗位；知识支持来自历史岗位规则，是建议分支。

点击节点可查看职责、验收条件、动作授权、记忆范围和来源。标记“规则参考”表示已有旧岗位说明，执行仍待接入；“已适配”表示有对应执行流程，不代表 Agent 正在运行或业务质量已验收。组织图不会创建 Agent，也不会自动扩大授权。

“运行架构”说明所有业务共用的四层：自动化中台 → Agent 执行 → 验收与交付 → 人的决策；它与公司的组织层级分别呈现。“业务流程”按部门展示内置模板和自定义流程。小红书的工作台、流程图和岗位说明保留在该渠道内。

## 第一次使用

1. 连接公司后台。网页访问 `/company` 时，未连接会进入配对页；配对只用于连接 T3 后台，不是模型账号登录。
2. 在「公司全景 → 配置团队与流程 → 部门与员工」添加部门、员工，设置汇报关系、职责、Codex 模型、推理强度和 skills，保存后组织图同步更新。
3. 在同一配置窗口的「工作流程」添加流程，选所属部门，按顺序添加执行阶段。每阶段选员工，填写工作、验收标准及 `outputs/` 下的实际交付文件。可加最后一位独立审核员工，须与制作员工不同；启用流程并保存。
4. 在「设置」启用公司派工，再到「业务流程」筛选部门并点击「新建任务」。只填任务要求，资料引用可留空。保存组织或流程配置本身不会调用模型。
5. 在「任务」查看当前阶段、成果和阻塞原因。任务的流程图使用创建时的配置；点击阶段可看负责人、模型、指令与验收标准。

模型列表来自本机 Codex 模型目录；目前执行桥只接通 Codex 订阅，其他 Provider 尚未接入。Skills 从 AI-Agent-System 的 shared-skills 列出，按选择交给当前岗位；依赖的 MCP、脚本或外部服务并不因关联 skill 而自动安装或授权，缺少必要能力时应阻塞。授权说明和记忆范围是岗位约束说明，不会授予发布、付费或读取私人资料的权限。

组织节点、员工执行配置和通用流程统一保存在 AI-Agent-System 的 `rules/ai-company/organization.json`；界面通过受限后台操作原子保存，有版本冲突检查和重复提交保护，不维护第二份规则源。小红书制作规则仍在同目录的 `rednote.json`。删除有下级或被流程引用的节点前，先移动下级、解除引用；已有任务不因删除配置而丢失。

通用流程当前支持最多 12 个顺序阶段，按所选流程或部门唯一启用流程派工；部门有多个流程时必须明确选择。每任务保存当时的流程、员工、模型、推理强度和 skills 关联快照，后续配置修改只影响新任务。Skill 文件内容仍由唯一规则源维护，按当前阶段按需读取；它们不是完整知识库副本。无独立审核阶段的流程会直接进入人工总审，不宣称已经过独立审核。

通用任务修改时选择「从哪个阶段重做」，仅使该阶段和后续成果失效，前面成果继续复用，旧总审失效。核心事实变化请选择首阶段。内置小红书仍使用封面／文案／事实三种修改范围，专用图像验收规则不变。

## 启动与关闭

先构建：`vp run --filter t3 build`。macOS 使用 `vp run company:service plan` 查看配置，再运行 `vp run company:service install`。它使用独立服务 `com.t3code-cn.ai-company`、端口 3775 和 `~/.t3-company-cn`，不会替换普通 T3 服务或触碰 `~/.t3/userdata`。

使用 `vp run company:service status|restart|update|uninstall` 管理。安装时使用 Node 26.12.1，将构建、所需运行依赖和 Node 复制到专用目录。运行不依赖开发工作副本；升级时先构建再 update，单纯重启用 restart。卸载只移除服务，不删除任务资料，也不停止已有 Herdr 终端；需要停止执行时先在公司面板点击停止。

后台入口是 `http://127.0.0.1:3775/company`。使用 T3 连接与配对功能接入该环境。需要新配对时运行 `~/.t3-company-cn/runtime/node ~/.t3-company-cn/app/bin.mjs pair --base-dir ~/.t3-company-cn`，配对凭据只用于自己的客户端。旧版 T3 前台没有公司面板时，先使用本次后台附带的网页，或更新中文版前台构建。

模块初始关闭。启用后才能创建任务；暂停新派工不会中断已经获准的执行。关闭前台不会停止这个独立后台；Mac 需要处于登录、未休眠状态。连接桌面内置后台时，面板会提示其生命周期限制。

## 流程图

进入 AI 公司 → 业务流程 → 小红书 → 流程图，也可从工作台的「先看流程图」或任务内的「在流程图中查看这项任务」进入。

六个节点依次为：你提出需求 → 研究 → 文案 → 设计 → 独立审核 → 你最终验收。宽屏使用带方向箭头的两行布局，窄屏按顺序纵向排列。点击节点查看负责人、职责、验收标准和仍有效的成果，再跳转任务详情或成果页。

任务选择器可切换「流程说明」和已有任务。流程说明不代表执行；真实进度来自持久任务状态，有效或复用成果以后台记录为依据，终端结束不会直接变成绿色完成。总审同时核对当前版本、有效审批与成果指纹。

下方「只改封面／修改文案／核心事实变化」仅预览影响范围，不调用模型、不修改任务。实际修改仍进入原任务提交；封面修改保留有效研究、正文与内页。独立审核失败时按问题退回相关岗位，自动返工最多三轮。页面还说明 T3 前台、常驻后台、Herdr 及规则、资料与记忆的分工。

## 任务与验收

创建内容任务即授权内部研究、文案、设计和独立审核；不授权发布、对外发送或新增付费。最终总审只绑定当前成果指纹，内容变化后旧总审失效。Herdr 的 done 不等于成果合格。

引用资料填写相对于 LLM-Wiki 的明确文件路径；首版支持最多 15 个、每个不超过 128 KiB 的文本资料。默认不会复制知识库。阶段输入只包含有效成果、当前反馈和已确认记忆。候选记忆需在面板确认，并选择仅当前任务或公司范围；可明确替代旧记忆或撤回，来源与替代关系保留。

设计必须交付实际 PNG/JPEG/WebP 图片，页数与封面数需要满足任务要求；缺图或重复页阻塞。审核必须有独立 Codex 会话逐图 `view_image` 工具调用记录并绑定输入指纹。图像生成能力依赖当前订阅与 Codex 能力，不能取得图片时如实阻塞。

修改封面会保留有效研究、正文和内页；修改正文会重做设计与审核；事实变化使全部依赖成果失效。执行中的任务先停止，再提交修改。每次执行使用独立工作区。恢复时阶段、版本和输入指纹均一致，且存在有效 Codex 检查点，就复制该任务的会话检查点并通过原生 resume 续接；否则使用最小交接。跨阶段、改版或输入变化不复用旧会话。

## 执行权限与接管

Codex 使用交互式 `--no-daemon`、workspace-write 沙箱与 on-request 权限模式。执行环境使用隔离的 CODEX_HOME，只复用现有 ChatGPT 订阅登录；不继承用户 MCP、hooks、付费 API 配置。首次部署需要本机存在文件形式的 Codex 订阅登录；没有登录或仅 API key 时阻塞。

Herdr 本身不是沙箱。当前隔离主要约束工作区写入；不能把同账号进程、只读文件访问或 terminal 标签当作强安全边界。后台不提供发布、外发或权限修改 API。

工具权限询问留在终端。用户点击人工接管后，自动验收与接力暂停；界面提供明确的终端按键，后台不会自动确认对话框。按键命令写入去重记录；响应丢失时不自动重发 Enter。

## 恢复与成本

任务、阶段、命令回执和派工意图在同一 SQLite 事务持久化，之后才启动进程。启动返回丢失时按运行标识、终端创建时间、进程 PID 和目录核对。结果不明时阻塞，不盲目重新启动。人工停止是持久状态；监控不会取消停止。

同时最多两个执行任务，每个阶段一个写入者；质量返工最多三轮。Herdr 事件驱动即时核对，程序定时检查补漏，闲时不会调用模型。输入、缓存输入、输出由可取得的 Codex 记录统计，图像次数等无法确认的数据标为未知。

同阶段恢复优先使用核对过的原会话，历史用量从新轮次累计中扣除，无法确认的计数保持未知。明确报告为临时网络错误时最多自动重试两次，并等待至少服务端指定时间。没有可靠结构化信息时保留现场等待；不猜测终端文本、不切换付费渠道。

## 实现与验证范围

岗位、验收和 skills 关联由 AI-Agent-System 中 `rules/ai-company/rednote.json` 维护。T3 在团队页显示源规则，执行时保存当前阶段的只读规则快照；源规则缺失时阻塞，不悄悄采用另一套业务规则。旧 Deal 的 receive_only 约束保留给历史任务。

源码：`apps/server/src/company`、`packages/contracts/src/company.ts`、`apps/web/src/components/company`。测试覆盖派工去重、并发、停止、恢复、增量失效、总审失效及文件边界。实际验证状态见 `docs/agent/state.md`；单元测试不代表真实模型与整套小红书业务已验收。

## 与参考文章的对应关系

[卡兹克的 Agent 自动化系统](https://x.com/Khazix0918/status/2117054043868860521)提供事件接入、规则分派、独立验收和人类决策回流的分工；原文软件 CI 的自动合并与发布不构成本公司的发布授权。[DeepSeek Harness 的 Super-agent 设计](https://x.com/DeepSeekHarness/status/2116857257245987236)补充统筹路由与任务执行分层、事件直达、按引用召回及状态与进程分离。第二篇属于架构探讨，原文也提示部分实验使用模拟任务，不能把实验调度收益等同于真实交付质量或省钱保证。

当前后台已实现自由配队、部门／流程的确定性路由、通用顺序任务与小红书模板，以及状态与成果持久化、同任务修改与恢复、有限返工及人工总审。公司级智能 Router、多渠道事件接入、通用决策复用、软件 CI 与对外发布尚未实现。界面中的架构总览明确标出这些缺口，不能将组织图看作完整自动化公司已经上线。

本机方案保留可续接状态，但不能在 Mac 休眠时计算。不采用默认推测性制作，不让监控自动扩张权限或预算。部门和岗位按需求扩展；上下文、私人资料和动作授权仍各有边界。
